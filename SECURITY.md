# Безопасность

## Как сообщить об уязвимости

Не публикуйте детали в открытых issue. Используйте
[приватное сообщение об уязвимости](https://github.com/satanikan/film/security/advisories/new)
(контакт также указан в `/.well-known/security.txt`).

## Что уже сделано

### Защита от фишинга

| Мера | Где | Зачем |
| --- | --- | --- |
| `frame-ancestors 'none'`, `X-Frame-Options: DENY` и JS-проверка в `main.jsx` | `server/security.js`, `src/main.jsx` | Сайт нельзя встроить в чужую страницу и подсунуть поверх него невидимые кнопки или поддельную форму (clickjacking) |
| `form-action 'self'` | CSP | Даже внедрённая форма не сможет отправить пароль на чужой домен |
| `autocomplete="username"`, `current-password`, `new-password` | формы входа и регистрации | Менеджер паролей подставляет пароль только на настоящем домене и «молчит» на фишинговой копии |
| Проверка параметра `?next=` | `src/lib/auth.jsx` → `safeRedirect` | После входа сайт перенаправляет только на свои страницы, а не на `https://evil.example` (open redirect) |
| `rel="noopener noreferrer"` и только `https:` у внешних ссылок | `src/Components/ExternalLink.jsx` | Открытая вкладка не может подменить наш сайт на фишинговый (reverse tabnabbing) |
| Плеер открывает только `https://archive.org/embed/<id>` с проверенным `id`, `sandbox` у iframe | `src/Components/Player.jsx`, `shared/validation.js` | В плеер нельзя подставить произвольную страницу |
| Подсказка с адресом сайта перед вводом пароля, напоминание в подвале | `src/Components/AntiPhishing.jsx` | Посетитель сверяет домен и знает, что пароль у него никогда не спрашивают |
| Тип жалобы «Подозрительная ссылка или фишинг» | `/error` | Посетители могут сообщить о поддельных копиях сайта |

### Защита от взлома

| Мера | Где |
| --- | --- |
| Строгая Content-Security-Policy: скрипты только со своего домена, без `unsafe-inline` и `eval`; шрифты свои (без Google Fonts) | `server/security.js` |
| Пароли хэшируются scrypt (~32 МБ памяти на проверку) с уникальной солью, сравнение за постоянное время | `server/auth.js` |
| Политика паролей: от 10 символов, запрет популярных паролей, пароля из одних цифр и пароля с логином | `shared/validation.js` |
| Блокировка входа на 15 минут после 5 неудачных попыток плюс лимиты частоты запросов на IP (вход, регистрация, API, жалобы) | `server/auth.js`, `server/security.js` |
| Одинаковый ответ и одинаковое время ответа для неверного пароля и несуществующего логина | `server/auth.js` |
| Сессии: случайный 256-битный токен, в памяти сервера хранится только его SHA-256; cookie `HttpOnly`, `SameSite=Strict`, `Secure` и префикс `__Host-` при HTTPS; срок жизни 7 дней, 2 дня бездействия; новая сессия при каждом входе | `server/auth.js`, `server/app.js` |
| CSRF: изменяющие запросы принимаются только с того же `Origin`, с проверкой `Sec-Fetch-Site` и только в формате JSON | `server/security.js` |
| Ограничение размера тела запроса (16 КБ), таймауты, ошибки без стек-трейсов, отключён `X-Powered-By` | `server/app.js`, `server/index.js` |
| Защита от prototype pollution: логины вроде `__proto__` не ломают хранилище | `server/auth.js` |
| Запрос поиска очищается от операторов Lucene; HTML из описаний archive.org вырезается, текст выводится без `dangerouslySetInnerHTML` | `server/archive.js` |
| Скрытое поле-ловушка против ботов в форме жалоб | `src/pages/Error.jsx` |
| HSTS (2 года, preload), `nosniff`, `Referrer-Policy: no-referrer`, COOP/CORP, `Permissions-Policy` | `server/security.js` |
| Файл данных создаётся с правами `0600`; сервер по умолчанию слушает только `127.0.0.1` | `server/store.js`, `server/index.js` |
| Зависимости на свежих версиях без известных уязвимостей (`npm audit`: 0), Dependabot | `package.json`, `.github/dependabot.yml` |

Все эти проверки покрыты тестами: `npm test`.

## Чек-лист перед публикацией

Часть защиты от фишинга настраивается не в коде, а у регистратора домена, в DNS и на хостинге:

1. **Только HTTPS.** Задайте `PUBLIC_ORIGIN=https://ваш-домен`, настройте редирект с HTTP на HTTPS и сертификат
   (например, Let's Encrypt). После проверки добавьте домен в [hstspreload.org](https://hstspreload.org).
2. **Статический хостинг** (Netlify, Cloudflare Pages): заголовки берутся из `public/_headers`. Для входа и регистрации
   всё равно нужен Node-сервер.
3. **Почта домена.** Злоумышленники рассылают письма «от имени» сайта. Настройте SPF, DKIM и DMARC с `p=reject`.
   Если почты на домене нет, опубликуйте `v=spf1 -all` и DMARC `p=reject`.
4. **CAA-запись в DNS**: сертификаты для домена сможет выпускать только ваш удостоверяющий центр.
5. **Регистратор**: включите двухфакторную аутентификацию и блокировку трансфера домена (registrar lock).
6. **Двухфакторная аутентификация** на GitHub, хостинге и в DNS-панели.
7. **Похожие домены**: время от времени проверяйте их (например, утилитой `dnstwist`) и жалуйтесь регистраторам на фишинговые копии.
8. **Секреты** (`.env`, `data/`) не попадают в git: они уже в `.gitignore`.
9. Перед сервером (nginx, Cloudflare) задайте `TRUST_PROXY`, чтобы лимиты запросов работали по реальным IP.

## Известные ограничения

- Сессии хранятся в памяти: после перезапуска сервера пользователям нужно войти заново. Для нескольких серверов
  нужен общий Redis.
- Хранилище пользователей — JSON-файл. Для большой нагрузки перейдите на PostgreSQL или SQLite.
- Двухфакторная аутентификация для пользователей сайта пока не реализована.
